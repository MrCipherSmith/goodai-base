# PRD: Phase 1 — Descriptions как триггеры, не как workflow

## Цель

Исправить descriptions во всех скиллах: они должны описывать **только условия активации** (когда использовать), а не пересказывать что скилл делает внутри.

## Проблема

Если description скилла пересказывает что он делает ("этот скилл анализирует X, затем делает Y, затем Z"), агент читает description и пропускает тело файла. Он считает, что уже понял workflow. В результате реальные инструкции в SKILL.md игнорируются.

## Решение

Description = только "Use when: <триггерные условия>". Максимум 1-2 предложения. Никакого описания шагов.

## Скоп

Все файлы `skills/*/SKILL.md` с frontmatter полем `description`.

### Критерии правильного description

- НЕ содержит глаголов действия ("анализирует", "создаёт", "запускает")
- Начинается с "Use when" или "Trigger when" или описания ситуации
- Не описывает шаги workflow
- Не дублирует название скилла
- Максимум 150 символов

## Acceptance Criteria

- [ ] Все descriptions в skills/*/SKILL.md проверены
- [ ] Descriptions нарушающие CSO — переписаны
- [ ] Каждый новый description протестирован: агент не может "срезать угол" зная только description
- [ ] Изменения не затрагивают тело SKILL.md файлов (только frontmatter)

## Файлы для изменения

Все `skills/*/SKILL.md` — только поле `description` в frontmatter.

## Приоритет

Высокий. Это системная проблема, влияющая на эффективность всех скиллов.
