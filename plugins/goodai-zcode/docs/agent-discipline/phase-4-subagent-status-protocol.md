# PRD: Phase 4 — Статус-протокол для субагентов

## Цель

Стандартизировать формат ответов субагентов: ввести четырёхуровневый статус-протокол вместо свободного текста.

## Проблема

Сейчас субагенты возвращают свободный текст. Оркестратор вынужден парсить естественный язык чтобы понять:
- Задача выполнена полностью?
- Есть проблемы которые надо знать?
- Субагент заблокирован?
- Нужен дополнительный контекст?

Это приводит к ошибкам интерпретации и silent failures (оркестратор думает что всё хорошо, а субагент тихо не справился).

## Решение

Каждый субагент ОБЯЗАН начинать свой финальный ответ с одного из четырёх статусов:

```
DONE — задача выполнена полностью, все acceptance criteria выполнены
DONE_WITH_CONCERNS — задача выполнена, но есть важные замечания для оркестратора
BLOCKED — не могу продолжить, нужно решение оркестратора
NEEDS_CONTEXT — недостаточно информации, нужны конкретные данные
```

### Формат ответа субагента

```
STATUS: DONE

## Выполнено
- [конкретный список сделанного]

## Изменённые файлы
- path/to/file.md — краткое описание изменения
```

```
STATUS: DONE_WITH_CONCERNS

## Выполнено
- ...

## Замечания для оркестратора
- [конкретное замечание и почему важно]
```

```
STATUS: BLOCKED

## Причина блокировки
[конкретная причина]

## Что нужно от оркестратора
[конкретный запрос]
```

```
STATUS: NEEDS_CONTEXT

## Чего не хватает
[конкретно какая информация нужна]

## Где искать
[предположение где это может быть]
```

## Скоп изменений

1. `skills/task-implementer/SKILL.md` — добавить обязательный статус-протокол в инструкции
2. `skills/job-orchestrator/SKILL.md` — добавить логику обработки каждого статуса
3. `skills/feature-dev/SKILL.md` — обновить subagent dispatch инструкции
4. Создать `rules/core/subagent-status-protocol.md` — отдельное правило для переиспользования

## Логика оркестратора для каждого статуса

| Статус | Действие оркестратора |
|---|---|
| DONE | Принять результат, перейти к следующей задаче |
| DONE_WITH_CONCERNS | Прочитать замечания, решить нужна ли корректировка |
| BLOCKED | Немедленно решить блокировку до следующего субагента |
| NEEDS_CONTEXT | Предоставить контекст и перезапустить субагента |

## Acceptance Criteria

- [ ] `rules/core/subagent-status-protocol.md` создан с полным описанием протокола
- [ ] `skills/task-implementer/SKILL.md` содержит обязательный статус в финальном ответе
- [ ] `skills/job-orchestrator/SKILL.md` содержит логику обработки всех 4 статусов
- [ ] Протокол описан достаточно подробно чтобы агент не мог "забыть" его применить

## Приоритет

Высокий. Критично для надёжности многоагентных оркестраций.
