# PRD: Phase 2 — Anti-Rationalization в ключевых скиллах и правилах

## Цель

Добавить секцию **Red Flags / Iron Law** в ключевые скиллы и rules, чтобы закрыть конкретные лазейки, которые LLM использует для обхода правил.

## Проблема

Текущие правила и скиллы описывают "что делать", но не называют дословно отмазки, которые агент генерирует под давлением. Агент может технически следовать букве правила, нарушая его дух.

Примеры типичных рационализаций:
- "Я напишу тесты после, сейчас важнее скорость"
- "Это слишком маленькое изменение для полного review"
- "Пользователь попросил быстро, значит качество вторично"
- "Я понял из description скилла — можно не читать дальше"
- "Это очевидно, подробный план не нужен"

## Решение

Добавить в ключевые скиллы блок:

```markdown
## Red Flags — Stop и перечитай правило если ты думаешь:

| Рационализация | Почему это неверно |
|---|---|
| "Это слишком простая задача для..." | Простота задачи не отменяет процесс |
| "Пользователь торопит, пропущу X" | Нарушение буквы = нарушение духа |
| ... | ... |

**ЖЕЛЕЗНЫЙ ЗАКОН**: [формулировка в верхнем регистре]
```

## Скоп

Приоритетные скиллы для добавления anti-rationalization:

1. `skills/code-review/SKILL.md` — рационализации вокруг "достаточно хорошего" ревью
2. `skills/feature-dev/SKILL.md` — рационализации вокруг пропуска фаз
3. `skills/issue-analyzer/SKILL.md` — рационализации вокруг неполного анализа
4. `skills/task-implementer/SKILL.md` — рационализации вокруг "быстрой" реализации
5. `rules/core/` — все файлы правил

## Процесс написания (TDD для документации)

1. RED: Запустить субагента без скилла, задать задачу под давлением — записать дословные рационализации
2. GREEN: Написать Red Flags закрывающие именно эти рационализации
3. REFACTOR: Найти новые лазейки, добавить

## Acceptance Criteria

- [ ] Каждый приоритетный скилл содержит секцию Red Flags с минимум 3 рационализациями
- [ ] Каждый rules файл содержит Iron Law (одно правило в caps)
- [ ] Рационализации написаны от первого лица агента ("я думаю...")
- [ ] Каждое опровержение конкретно, не абстрактно

## Приоритет

Высокий. Без этого правила могут не выполняться даже когда агент их "читает".
