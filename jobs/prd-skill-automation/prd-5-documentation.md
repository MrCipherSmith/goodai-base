# PRD: Documentation System for goodai-base

**Version:** 1.0.0
**Date:** 2026-04-10
**Status:** Draft

---

## 1. Overview

goodai-base is a growing knowledge base with 20+ skills, 15+ rules, and a complex orchestration system. Currently it lacks auto-generated catalogs, onboarding guides, and sync automation. Developers must manually read AGENTS.md to discover skills and rules, which is slow and error-prone as the system grows.

This PRD covers a documentation system that auto-generates human- and AI-readable catalogs from skill/rule metadata, generates changelogs, and keeps everything in sync via GitHub Actions.

---

## 2. Goals

- Auto-generate a skill catalog from `SKILL.md` frontmatter across all skills
- Auto-generate a rules catalog from `.mdc` files in `rules/core/`
- Produce a developer onboarding guide
- Generate CHANGELOGs from git commits
- Run sync automatically via GitHub Actions (monthly + on skill/rule change)

---

## 3. Non-Goals

- Rewriting existing SKILL.md or .mdc files
- Replacing AGENTS.md as the routing table
- Public-facing website or hosted docs

---

## 4. Functional Requirements

### FR-1: Skill Catalog Generator
- Script `scripts/generate-skill-catalog.sh`
- Reads all `skills/*/SKILL.md` files
- Extracts: `name`, `description`, `version`, `use_when` (if present), `allowed-tools`, `model`
- Outputs `docs/skill-catalog.md` — table with name, description, version, trigger keywords
- Also outputs `docs/ai/skill-catalog.yaml` — machine-readable for hook consumption

### FR-2: Rules Catalog Generator
- Script `scripts/generate-rules-catalog.sh`
- Reads all `rules/core/*.mdc` files
- Extracts frontmatter: `name`, `description`, `applies_to`
- Outputs `docs/rules-catalog.md` — table with rule name, description, stack area

### FR-3: Onboarding Guide
- Script `scripts/generate-onboarding.md` or static file maintained manually
- Sections: What is goodai-base, How skills work, How rules work, How to add a skill, How to sync, Quick reference table
- Target audience: new engineer or AI agent navigating the system cold

### FR-4: Changelog Generation
- Integrates with existing `skills/changelog` skill
- Script `scripts/generate-changelog.sh` — runs between tags or last N commits
- Outputs `CHANGELOG.md` at root

### FR-5: GitHub Actions Workflow
- `docs-sync.yml` — triggers on push to `skills/**` or `rules/**`, runs catalog generators, commits with `[skip ci]`
- `docs-monthly.yml` — cron monthly, generates changelog + full catalog refresh

### FR-6: AI-Readable Catalog Format
- `docs/ai/skill-catalog.yaml` format:
  ```yaml
  skills:
    - name: feature-analyzer
      description: "..."
      keywords: [analyze, branch, cross-repo]
      version: 2.4.0
  ```
- Used by skill evaluation hook (PRD-1) as the trigger source of truth

### FR-7: Frontmatter Validation
- Generator warns (non-blocking) if `name` or `description` is missing
- Logs warnings to stdout for GitHub Actions annotations

### FR-8: docs/README.md Index
- Auto-updated by generators with last-generated timestamp
- Links to all generated docs

---

## 5. Non-Functional Requirements

- **NFR-1:** All generators must be idempotent (safe to re-run)
- **NFR-2:** Generation completes in <30s for current skill/rule count
- **NFR-3:** Bash-only scripts — no Node.js or Python dependency
- **NFR-4:** Generated files include `<!-- generated by scripts/... on {date} -->` header
- **NFR-5:** Graceful degradation — if `yq` not installed, falls back to grep-based parsing
- **NFR-6:** GitHub Action uses `actions/checkout@v4`, no third-party actions for security

---

## 6. Constraints

- Scripts must be read-only consumers of `skills/` and `rules/` — never modify source files
- Naming must follow `documentation-management.mdc` conventions
- GitHub Action commits use `[skip ci]` to avoid loops
- Must not conflict with existing `sync-skills.sh` or `validate-skills-before-sync.sh`

---

## 7. Edge Cases

| Case | Handling |
|------|----------|
| SKILL.md missing frontmatter | Log warning, skip file, continue |
| Required field missing | Warn, use placeholder `"(undefined)"` |
| No new commits since last run | Changelog outputs "No changes" section |
| Empty diff | Skip GitHub Action commit step |
| No SKILL.md in a skills/ subdirectory | Skip directory with warning |
| Duplicate skill names | Warn, last-one-wins in catalog |
| Output directory missing | Auto-create `docs/` and `docs/ai/` |

## 8. Acceptance Criteria (Gherkin)

```gherkin
Feature: Skill Catalog Generation
  Scenario: Catalog generated from all skills
    Given skills/ contains 20 SKILL.md files with valid frontmatter
    When scripts/generate-skill-catalog.sh runs
    Then docs/skill-catalog.md contains 20 rows
    And docs/ai/skill-catalog.yaml is valid YAML with 20 entries
    And each entry has name, description, and keywords

  Scenario: Missing frontmatter handled gracefully
    Given one SKILL.md has no frontmatter
    When the script runs
    Then a warning is printed to stdout
    And the catalog is generated for the remaining 19 skills

Feature: Rules Catalog Generation
  Scenario: Rules catalog generated
    Given rules/core/ contains 15 .mdc files
    When scripts/generate-rules-catalog.sh runs
    Then docs/rules-catalog.md contains 15 rows

Feature: GitHub Actions Docs Sync
  Scenario: Auto-sync on skill change
    Given a developer pushes a new SKILL.md to skills/new-skill/
    When the docs-sync GitHub Action triggers
    Then generate-skill-catalog.sh runs
    And docs/skill-catalog.md is updated and committed with [skip ci]

Feature: Changelog Generation
  Scenario: Changelog from git log
    Given commits exist between v1.0 and v2.0 tags
    When scripts/generate-changelog.sh v1.0 v2.0 runs
    Then CHANGELOG.md contains grouped sections (feat, fix, chore)
    And each entry references the commit hash
```

## 9. Implementation Plan

1. `scripts/generate-skill-catalog.sh` — parse SKILL.md files, output markdown + yaml
2. `scripts/generate-rules-catalog.sh` — parse .mdc files, output markdown
3. `scripts/generate-changelog.sh` — wrap existing changelog skill as a script
4. `docs/onboarding.md` — authored manually, reviewed quarterly
5. `.github/workflows/docs-sync.yml` — push trigger on skills/** and rules/**
6. `.github/workflows/docs-monthly.yml` — cron monthly changelog + catalog

---

## 10. Dependencies

- `prd-1-skill-eval-hook.md` — consumes `docs/ai/skill-catalog.yaml` as trigger source
- Existing `sync-skills.sh` — must not conflict; docs-sync runs after it
- `skills/changelog` — script wrapper delegates to this skill
