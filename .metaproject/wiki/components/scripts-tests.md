# Module scripts/tests

## Overview

`scripts/tests` holds the **unit/integration tests** for the tooling under `scripts/src`. Tests run with Bun (`cd scripts && bun test`) and guard skill sync contracts, validator gates, catalog generators, and shared helpers so changes to agent integration do not silently break multi-tool deployment.

## How it works

- One test file per major CLI script (e.g. `sync-skills.test.ts`, `validate-skills-before-sync.test.ts`, `generate-skill-catalog.test.ts`).
- Shared unit tests under `scripts/tests/shared/` cover frontmatter parsing, fs helpers, checksums, and AGENTS.md utilities.
- Tests use fixtures / temp dirs rather than writing into `~/.claude` or `~/.cursor`, so CI stays hermetic.
- Cross-module graph imports are none: tests import production code under `scripts/src` and assert behavior/contracts.

## Key concepts

- **Pre-sync contract** — missing `SKILL.cursor.md` / `SKILL.codex.md` must fail validation (current policy).
- **Fallback sync** — when a platform profile is absent, sync may use `SKILL.md` (behavior covered in sync tests).
- **Catalog regeneration** — generators must emit stable, deterministic docs/registry artifacts.

## Main flows

1. **Developer change to sync-skills**  
   Edit `scripts/src/sync-skills.ts` → run `bun test scripts/tests/sync-skills.test.ts` (or full suite) → then manual `bun run sync-skills` on a sandbox config.

2. **New skill without profiles**  
   Validator tests assert FAIL without cursor/codex profiles; documents the gate that blocked incomplete upstream skills.

3. **CI / health**  
   Metaproject testing module indexes these files as the primary test surface (Bun; frameworks detected as configs + 21 test files at project level).
