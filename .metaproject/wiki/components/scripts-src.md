# Module scripts/src

## Overview

`scripts/src` is the operational core of **goodai-base tooling**: Bun/TypeScript CLIs that keep skills and rules consistent across agent platforms. It owns validation gates, multi-tool skill sync, catalog/registry generation, plugin bundles (Codex/ZCode), and agent bootstrap helpers. Runtime entry is via `scripts/package.json` (`bun run sync-skills`, etc.).

## How it works

Scripts fall into four layers:

1. **Gate / validate** — `validate-skills-before-sync.ts` checks skill frontmatter and required platform profiles; `validate-rules-json.ts` checks `rules.json` vs `AGENTS.md`.
2. **Sync** — `sync-skills.ts` copies `SKILL.<platform>.md` (or falls back to `SKILL.md`) into each configured tool skills dir and syncs `AGENTS.md`. Related: `sync-agents.ts`, `sync-zcode.ts`.
3. **Generate** — catalog/registry/docs and plugins: `generate-skill-catalog.ts`, `generate-skill-registry.ts`, `generate-rules-catalog.ts`, `generate-rules-json.ts`, `generate-agents.ts`, `generate-codex-plugins.ts`, `generate-zcode-plugin.ts`.
4. **Detect / deploy** — `detect-context.ts`, `detect-models.ts`, `deploy-skill-hook.ts` support setup and project hooks.

Shared helpers live in `scripts/src/shared` (fs utils, frontmatter, checksums) — see [scripts-src-shared](scripts-src-shared.md).

## Key concepts

- **Canonical skill** — `skills/<name>/SKILL.md` is source of truth; platform files (`SKILL.cursor.md`, …) are optional overrides.
- **sync_tools** — `goodai.config.json` selects which agents receive skill copies.
- **Pre-sync validation** — hard gate before sync (cursor/codex profiles required by current validator).
- **Plugin targets** — ZCode/Codex are not plain skills dirs; they use generated plugin bundles.

## Main flows

1. **Install / update skills on tools**  
   `cd scripts && bun run sync-skills` → validate → copy skills + AGENTS.md to configured tools.

2. **Author a skill**  
   Add `skills/<name>/SKILL.md` (+ platform variants) → register in `AGENTS.md` → `generate-skill-catalog` → `sync-skills`.

3. **ZCode / Codex plugin refresh**  
   `generate-zcode-plugin` / `generate-codex-plugins` → `sync-zcode` (or Codex plugin install path).
